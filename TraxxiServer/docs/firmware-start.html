TraxxiServer: firmware first

Version 0.1.0 / separate CYD foundation for the Traxxis Server concept.

What this milestone does

A new Arduino sketch mounts a FAT32 SD card, loads configuration, joins the business router, sets a device hostname, and serves an owner-password-protected status page from /traxxi/www. A read-only GET /api/v1/status reports the name, IP address, discovery state, versions, uptime, and formatted card capacity/usage in bytes. Configuration and credentials are never served.

The page introduces HomePage, Employee Roster, Schedule, and Document Share as planned apps. Only the foundation status page is working; there are no business records, employee logins, uploads, FTP, WebDAV, installer, or document previews yet.

All project files are inside TraxxiServer. The existing CrewBoard firmware and assets are unchanged. Use a separate device/card for testing: flashing this sketch onto a CrewBoard device replaces the firmware on that device.

Product context: business-server brainstorm and Traxxis sales concept.

Bench use only

This is HTTP with Basic authentication, not HTTPS. Passwords and traffic are not encrypted. Use a unique test password on a trusted, isolated local network, without port forwarding. Do not treat this as production-ready or store real personnel information. Production deployment needs verified HTTPS, account roles, permission checks, backup/restore, and hardware reliability testing.

The SD configuration contains plaintext credentials. Keep it out of Git, screenshots, and shared backup locations. This project's ignore rules cover sd-card/config.json, not arbitrary copies elsewhere.

Hardware and build

  • ESP32-2432S028R CYD, reliable 5 V supply, FAT32 microSD. Start with a dedicated 32 GB card.
  • SD uses CS 5 and the ESP32 default VSPI pins (SCK 18, MISO 19, MOSI 23); display backlight uses GPIO 21.
  • Install Espressif ESP32 core 3.3.12, TFT_eSPI, and ArduinoJson 7.x. WebServer, WiFi, SD, ESPmDNS, and NetBIOS come with the ESP32 core.
  • Configure TFT_eSPI for the actual CYD display. A common ILI9341 setup uses MISO 12, MOSI 13, SCLK 14, CS 15, DC 2, RST -1. Board revisions vary; verify your hardware.
  • Open firmware/TraxxiServer/TraxxiServer.ino in Arduino IDE. Select ESP32 Dev Module: 240 MHz CPU, 80 MHz flash, QIO (DIO if needed), 4 MB flash, default partition, 115200 upload speed.

Compile from the TraxxiServer folder with an installed arduino-cli:

arduino-cli compile --fqbn "esp32:esp32:esp32:CPUFreq=240,FlashFreq=80,FlashMode=qio,FlashSize=4M,PartitionScheme=default,UploadSpeed=115200" --build-path ".\build" ".\firmware\TraxxiServer"

If the CLI is not on PATH, Arduino IDE on Windows may supply it at C:\Program Files\Arduino IDE\resources\app\lib\backend\resources\arduino-cli.exe. Upload only after selecting the intended device's COM port.

Prepare a separate SD card

  1. Use an empty, already FAT32-formatted card. Back up any existing contents before changing a card.
  2. Copy the contents of sd-card to the card root.
  3. Copy config.sample.json to /config.json on the card, and replace every placeholder. The sample will intentionally fail validation if left unchanged.
  4. Insert the card and boot the separate test CYD. Read its screen or Serial monitor at 115200 baud.

  • wifi.ssid: the router's 2.4 GHz Wi-Fi network name, 1-32 printable ASCII characters.
  • wifi.password: 8-63 printable ASCII characters, or a 64-character hexadecimal WPA key. This starter does not support open networks or enterprise Wi-Fi.
  • hostname: 1-15 ASCII letters/digits/hyphens, beginning and ending with a letter/digit. Normalized to lowercase. Omit the field for traxxi-server; an explicitly invalid, null, or empty value stops startup. Do not append .local.
  • serverName: friendly business-server title, 1-64 printable ASCII characters.
  • admin.username: 1-32 printable ASCII characters, without spaces or colons.
  • admin.password: unique 16-128 printable ASCII characters, different from the Wi-Fi password. This is the sole owner login in this milestone, not the planned three-role account system.

Configuration must be a JSON object of at most 4096 bytes. Missing files, malformed or invalid config, missing web assets, SD failure, or initial Wi-Fi failure stop startup with a screen/Serial error. There is no fallback access point or web config editor. Correct the card/router and reboot. All configuration changes require a restart.

Open the server

On the same local network, open the displayed http://IP-ADDRESS/ and enter the owner credentials when the browser prompts. On compatible clients, use http://traxxi-server.local/ (or your configured hostname). The firmware advertises HTTP over mDNS and supplies its hostname to DHCP; NetBIOS is attempted for compatible Windows clients.

Plain-name access depends on the router/client, and mDNS can be blocked by guest networks, client isolation, multicast filtering, or VLANs. Discovery failure is logged and does not stop HTTP. Reserve an IP address in the router as a fallback. Use distinct hostnames for different devices. After an established Wi-Fi connection drops, automatic reconnection is enabled; HTTP/discovery restart when the connection/address changes.

Only the three exact web asset routes and status API are exposed. Unknown paths, including /config.json and /data, return 404 after authentication. Non-GET requests to known routes return 405. Uploads and card writes are not supported.

Storage is a validation target, not a promise yet

The concept targets a 32 GB card, around 2 GB reserved for apps, and 20 GB advertised shared-file capacity. This firmware reports actual filesystem capacity and usage; it does not reserve space or enforce a shared-file quota. GiB displayed in the browser uses 1024-based units and differs from marketed GB.

A 1 TB card is not a verified capability. Large cards commonly arrive as exFAT; this build expects FAT32 and does not enable exFAT. Card capacity does not remove ESP32 RAM, transfer, filesystem, or concurrency limits. Test the exact card and filesystem before offering expansions. FAT32 also limits an individual file to less than 4 GiB.

Before any card copy or manual backup, power down the CYD. Copying the whole card includes credentials; protect that copy. Backup restoration and interrupted-write recovery still need testing before business data is introduced.

Validation and next milestone

With Node.js 22+, run npm test and npm run check inside TraxxiServer; no npm packages are required. Browser tests execute the real status script against success/failure responses. Native tests execute the production configuration parser with ArduinoJson headers, MSVC C++ tools, and Windows; they explicitly skip if those tools are absent. An ESP32 compile is a separate required check.

Initial verification: all four automated tests passed without skips, JavaScript syntax checking passed, and the separate sketch compiled with ESP32 core 3.3.12 on November 10, 2026. The default 4 MB build used 1,077,230 bytes (82%) of the application partition and 50,884 bytes (15%) of static RAM. This leaves limited flash headroom for future TLS/features; runtime heap and performance still require measurement. No device was flashed and no hardware/network acceptance tests were performed.

Hardware acceptance checklist (not implied by a successful compile):

  1. Boot the dedicated 32 GB card and verify TFT/Serial name, IP, and network without passwords.
  2. Verify no/wrong credentials return 401 and correct credentials open the home page/status API.
  3. Verify formatted capacity matches the card and no status payload includes credentials.
  4. Test invalid config, missing assets, missing SD, and unreachable router; verify visible errors and no unauthenticated server.
  5. Check IP, mDNS, and Windows name access; test a router disconnect/reconnect and discovery failure fallback.
  6. Check unknown paths and non-GET methods, then test sustained operation and refreshes from target phones/computers.

Next: define the shared data/API and employee/administrator/owner permissions, verify encrypted access on hardware, then implement Employee Roster, vacations/holidays, and the admin-upload/employee-read Document Share workflow. Define versioned app manifests before building an installer. Keep FTP out of the first release.
